# realme Buds Air8 — Find your frequency

45-second product concept film, 1920×1080 at 60 fps. Actual **Master Grey** product photographs, eight scenes, five preferred transition families and the supplied **Glass and Alloy** soundtrack. No moving retailer/reference footage, invented hardware model or generated product image is used.

From the repository root:

```sh
npm run buds:prepare
npm run buds:sound
npm run buds:build
npm run buds:check
npm run buds:preview
npm run buds:render
```

The existing local production media must be present. Preview: http://localhost:3028/#project/realme-buds-air8 . Delivery: `out/realme-buds-air8/realme-Buds-Air8-Find-Your-Frequency.mp4`.

Edit scene artwork/motion in `scenes.mjs`, frame boundaries in `sequence.mjs` and full-scene handoffs in `transitions.mjs`. `artwork.mjs` samples integer frames; the GSAP clock in index.html is generated by the build script. Rebuild after source edits. The central Remotion engine and previous projects remain independent.

The original product assets/evidence live in `assets/Products/realme-buds-air8` with URLs/hashes/dimensions. Preparation checks the originals, keys only the near-white backdrop and extracts the two photographed earbuds as separate connected silhouettes. It preserves source RGB/aspect ratios and never reconstructs unseen product surfaces. Local project images/fonts/audio and final exports are Git-ignored media, as elsewhere in the studio.

Read [verified claims](FACTS.md), [creative blueprint](project.md), [review evidence](REVIEW.md), [audio handoff](AUDIO.md) and [credits](CREDITS.md). Attach master.wav once: it already includes music and effects. The separate music/effects WAVs and frame-locked cue/source records are retained for later edits.

Studio DOM craft inspection cannot assess paint changes inside the canvas and reports a dead-stretch warning. Native canvas sampling, backward scrubbing and decoded-video pixel comparisons are the relevant independent checks; do not hide the warning with a false data-hold annotation.
